# Handling review feedback

Read the full feedback and understand the requested outcome. Verify each finding against the code, requirements, and actual behavior before editing.

Clarify ambiguous feedback before partially implementing it. Reject incorrect, out-of-scope, or speculative suggestions with concrete evidence; do not add flexibility for hypothetical needs.

Apply accepted findings individually when practical. Validate the affected behavior after each change so failures stay attributable, then report what was accepted, rejected, or left unresolved.
